# 扩展管理器（ext-manager）v1.2.0

> QQ Agent 插件：**让机器人帮你清理技能与插件**。
> 列出当前装了什么、把不要的**整个移除**（文件夹移到回收区 + 清掉配置）。

---

## 0. 权限模型（两种模式）

**本插件靠「主人识别」（owner-identity）插件来判定"谁是主人" —— 没启用它，删除权限校验会失效。**

| 「主人识别」状态 | 后果 |
|---|---|
| **启用 + 填了主人 QQ 号** | ✅ 正常：只有主人能删、能看列表 |
| 装了但**没启用** | ⛔ **本插件拒绝一切操作**（包括主人自己），并提示先去启用 |
| **压根没装** | ⛔ 同上 |
| 启用了但**没填主人号** | ⛔ 同上（没有名单 = 谁也认不出） |

### 开放模式：一个开关放开所有操作

设置里的「**开放模式：允许任何人查看与修改**」（配置键 `allowViewer`）是**总开关**：

| 开放模式 | 谁能查看列表 | 谁能删除/清理 |
|---|---|---|
| **关闭**（默认） | 只有主人（且需启用主人识别） | 只有主人（且需启用主人识别） |
| **打开** | **任何人** | **任何人** |

打开它 = **完全关掉权限校验** —— 适合"群里都是自己人"的场景。
⚠️ 打开后别人也能删你的技能和插件，请自行判断。

> 代码层面：**三个工具（ext_list / ext_remove / ext_purge）都会先做这个检查** —— 主人识别没就绪时一律返回"请先启用「主人识别」"，不做任何实际操作。

**所以第一次用之前，请务必**：

1. 设置 → 插件 → 启用「**主人识别**」
2. 在它的设置里填好**主人 QQ 号**（多个用逗号分隔）
3. 再启用本插件

> **为什么选择"拒绝"而不是"放行但提醒"**（使用者 2026-10-12 明确要求）：
> 删除是高危操作，判不出"谁是主人"时**宁可拒绝**，也不能让任何群友都能删你的技能和插件。
> 代价是：没装主人识别时本插件完全不能用 —— 这是有意的（先配好权限，再用工具）。

## 1. 为什么是插件，不是技能

| | 技能（skills/） | 插件（plugins/） |
|---|---|---|
| 运行环境 | 受限沙箱 | **主进程**，有文件系统权限 |
| 能否移动目录 | ❌ 做不到 | ✅ 可以 |
| 适合做删除吗 | 不适合 | **适合** |

删除是破坏性操作，要动 `skills/`、`plugins/` 下的目录 —— **只有插件有权做**。
（也不适合做成"技能"，因为技能删不了别人。）

---

## 2. 两个工具

| 工具 | 作用 | 权限 |
|---|---|---|
| **`ext_list`** | 列出当前装的技能与插件：id、名称、版本、是否启用、**是否加载失败**、**目录结构是否异常** | 默认仅主人（可在设置里放开查看） |
| **`ext_remove`** | 把一个或多个扩展**整个移除**（移到回收区 + 清配置） | **仅主人** |

### `ext_list` 会额外标出"有问题的条目"

```
⚠️ 有 2 个条目看起来有问题（清单文件缺失，或目录多套了一层）：
  · skills/reply-meme          ← 实际是 skills/reply-meme/reply-meme/skill.json
  · plugins/some-broken-one
```

「目录多套了一层」是最常见的安装故障：解压/克隆时多包了一层，
核心在顶层找不到 `skill.json` / `plugin.json`，界面上就显示「缺少 skill.json」。这两个正好删掉重装。

## 3. 怎么用（对话式）

```
群友：@机器人 看看装了哪些技能
机器人：（列出技能与插件，标出有问题的条目）

群友：@机器人 把那个 reply-meme 删掉
机器人：要删除技能 skills/reply-meme 吗？它会移到回收区（可恢复），配置也会清掉。
       确认吗？
群友：删
机器人：✅ 已移除：技能 `reply-meme`
       （文件夹移到 _removed/2026-10-12T15-19-01-009Z/，想找回就从这里移回去）
```

**要点**：
- `ext_remove` **必须带 `confirm: true`** —— 防止模型自作主张删除
- 默认**只有主人**能删（走「主人识别」插件的判定；没装/没启用主人识别时不设权限）
- **不是永久删除**：文件夹移到 `resources/app/_removed/<时间戳>/<skills|plugins>/<id>/`

## 4. 删除的实现（两条路）

```
ext_remove 被调用
   │
   ├─ ① 调核心接口 POST /api/skills/delete
   │      （端口从 config.server.port 读，多实例会试 3210/3211/3212/3310/3410）
   │      核心会：移到 _removed/ + 清配置 + 重扫 → 工具与提示词立刻下线
   │      ✅ 首选：最干净
   │
   └─ ② 接口不可用（核心版本较老）→ 降级
          插件自己把目录移到 _removed/
          + 自己清 config.skills 里的配置
          + 尝试 POST /api/skills/reload 让核心重扫
          + 重扫不了就提示「重启一次 QQ Agent」
```

**为什么优先走核心接口**：核心那边还会做 `reloadSkills()`（重扫 + 让工具/提示词下线）。
插件自己删目录的话，内存里的注册表还在 —— 得靠重扫或重启才能清干净。

## 4.1 回收区定期清理（v1.1.0 加）

删除的扩展堆在 `resources/app/_removed/` 里，**不清会一直占磁盘**。所以：

| 机制 | 说明 |
|---|---|
| **自动清理** | 插件启用期间，每 **6 小时**看一次；把**超过保留期**（默认 **7 天**）的条目删掉 |
| **保留期可调** | 设置项「**回收区保留天数**」，填 `0` 就关掉自动清理 |
| **定时器生命周期** | 用插件的 `activate` 起、`deactivate` 停 —— 关掉插件或热重载时**一定会清掉定时器**，不会泄漏 |
| **手动清理** | `ext_purge` 工具：说「清理回收站」，或带 `{"dryRun":true}` 先预览、`{"all":true}` 无视保留期全清 |

**怎么判断"过期"**：回收区目录名是 ISO 时间戳（如 `2026-10-12T15-18-40-306Z`），
按名字解析时间；解析不了就退回用目录的修改时间。这样即使用户手动往里塞文件夹也能处理。

> 为什么默认留 7 天：删错了还有一周时间能把文件夹移回 `skills/` 或 `plugins/` 恢复。
> 觉得没必要留那么久，就把保留天数改小。

## 5. ⚠️ 踩坑记录（值得知道）

| 坑 | 说明 |
|---|---|
| **数据目录会被重定向** | `config.json` 不一定在 `resources/app/data/` —— 环境变量 `QQ_AGENT_DATA_DIR` 或 `PROFILE` 会把它挪到别处（本机实测在顶层 `data/`）。插件**必须多路径找配置**，否则权限校验会读空 → **静默失效**（非主人也能删！） |
| **插件 API 没有 `configOf`** | 插件只能读**自己**的配置（`api.config()`）。要读别的扩展的配置，只能自己读 `config.json` |
| **`plugin.json` 里别用裸双引号** | 提示词内容里的中文引号会截断 JSON 字符串 → 整个插件加载失败。用「」 |
| **删自己会断** | `ext_remove` 显式拒绝 `ext-manager` 自己 —— 删一半插件没了，操作就断了。要删它请去界面点 🗑 |
| **路径穿越** | id 必须匹配 `^[A-Za-z0-9._-]+$` 且不以 `.` 开头 |

## 6. 设置项

| 配置 | 默认 | 作用 |
|---|---|---|
| `allowViewer` | `false` | **开放模式总开关**：打开后任何人可查看/删除/清理。关闭时只有主人能做（且需启用主人识别） |

## 7. 目录结构

```
ext-manager/
├── plugin.json    清单：2 个工具、1 个设置项、提示词
├── index.js       主体：ext_list / ext_remove
└── README.md      本文件
```

**依赖**（可选）：
- **主人识别（owner-identity）**（**强烈建议启用**）：用来判定"谁是主人"。
  ⚠️ **没装/没启用时不设权限限制** —— 详见上面 §0，**这等于谁都能删扩展**
- **核心的 `/api/skills/delete`**：首选删除路径。没有它会自动降级（见 §4）

## 8. 发布到市场

本插件是**自包含**的（`plugin.json` + `index.js` + `README.md`），可以直接发布：

1. 先在市场登录账号
2. 到「插件」页找到本插件，点卡片行尾的 **⬆** 上传按钮
3. 填显示名/简介 → 过验证码 → 得到**安装口令**
4. 把口令给别人，他们输入口令即可安装

> ⚠️ 别人装上后，**首选删除路径依赖核心的 `/api/skills/delete` 接口**。
> 如果对方的核心版本较老，插件会自动降级（自己移目录 + 尝试重扫），并在结果里提示升级。
