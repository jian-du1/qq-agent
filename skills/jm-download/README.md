# 禁漫漫画下载（jm-suomingor）v2.3.1

给 QQ Agent 加的一个**技能（Skill / LLM 型）**：群友发来禁漫天堂（JMComic）的漫画 ID，机器人在**后台异步**下载整本 → **还原竖切打乱** → **合成 PDF** → **上传到提出请求的那个会话**（群文件 / 私聊文件），完成后自动回帖汇报。

- 类型：**技能（Skill）** → 放 `skills/jm-suomingor/`（唯一能注册工具给模型的地方）
- 版本：2.3.0
- 运行时依赖：**无硬依赖**（用环境自带 `fetch`；`opencc-js`、Python+Pillow 缺了都只是降级，不会坏）
- 默认下载位置：`<QQ Agent 安装目录>/resources/app/data/jm-suomingor/jm-<ID>/`
- 内容分级：**成人向工具**，只响应群友主动请求，不主动推荐

---

## 1. 功能一览

| 功能 | 说明 |
|---|---|
| 异步下载整本 | 多章节全下、防爬竖切自动还原、并发可调；模型回合秒回，不卡对话 |
| PDF 合成 + 上传 | Python+Pillow 合成 PDF（画质/尺寸可调），自动传回请求会话；>20MB 自动分卷或拒绝（可设） |
| 完成信息卡 | 下载完成发一张「简介信息卡」图片：封面 + 标题 + JM 编号徽章 + 作者/标签/规模 + 底部通栏简介 |
| 今日JM | 把本地书架渲染成**封面网格信息图**（每张卡带 JM 编号徽章），删除的本子自动从图中消失 |
| 更新JM | 站点当日新上架/新章节清单，同样渲染成信息图；采集器每 30 分钟自动抓，每晚 12 点自动清空重来 |
| 按群开关 | 机主自由选择哪些群能用：群里发「开启JM / 关闭JM / JM群列表 / JM所有群开放」 |
| 中文处理 | 繁→简（OpenCC）、日文标题自动翻译成简体中文（结果按原文缓存，只翻一次） |
| 任务控制 | 「暂停下载 / 继续下载 / 删除JM」由前置钩子直接处理，模型挂了也能用 |
| 成品缓存 | 同一 ID 12 小时内重复请求直接重发文件，不重新下载 |
| 自动清理 | 本地目录按天数清理；群文件可设到期自动删 |

## 2. 安装

### 方式 A：插件市场（推荐）
在 QQ Agent 里上传本 ZIP（内含 `jm-suomingor/` 文件夹），或从市场安装后启用技能即可。

### 方式 B：手动安装
把整个 `jm-suomingor/` 文件夹放到：

```
<QQ Agent 安装目录>/resources/app/skills/jm-suomingor/
```

重启 QQ Agent（`systemctl restart qq-agent`），日志里出现
`禁漫漫画下载技能已加载` 即成功。

### 可选增强（缺了不影响核心功能）
| 依赖 | 作用 | 缺了会怎样 |
|---|---|---|
| Python 3 + Pillow | 竖切还原、PDF 合成、信息图渲染 | 下载/控制/列表仍可用；不生成 PDF、不发图片卡 |
| `opencc-js`（npm） | 繁→简完整字库 | 退回内置 152 字小表，生僻字可能不变 |
| 服务器字体（如 `fonts-wqy-microhei`） | 信息图里的数字/中文正常显示 | 信息图会出现「口口」豆腐块 |
| cron 定时任务 | 「更新JM」的每日自动采集 | 不装则「更新JM」列表为空，其余不受影响 |

每日采集 cron 示例（ubuntu 用户，每 30 分钟一次）：

```
*/30 * * * * /home/ubuntu/node/bin/node /home/ubuntu/qq-agent/skills/jm-suomingor/daily_updates.mjs --quiet >> /home/ubuntu/qq-agent/data/jm-suomingor/daily-cron.log 2>&1
```

采集器会在每天 0 点（UTC+8）自动清空当天清单重新积累，无需人工干预。

## 3. 怎么用（群里 @机器人 说）

### 下载与任务控制
| 你说的 | 会发生什么 |
|---|---|
| `jm123456` / `JM-123456` / `帮我下 123456` | 秒回「已开始处理」→ 后台下载→还原→合成 PDF→上传→回帖汇报（带简介信息卡） |
| `https://18comic.vip/album/123456/xxx`（整条链接） | 同上，自动从链接取 ID |
| `@机器人 123456` | 同上（只有 @ 了机器人的纯数字才这样判，避免误伤普通数字） |
| 再次发同一个 ID | 命中最近 12 小时成品，**直接重发文件**，不重新下载 |
| `暂停下载 JM123456` | 暂停排队/下载中的任务（已下好的图保留） |
| `继续下载 JM123456` | 恢复被暂停的任务 |
| `删除JM123456` | 删除本地文件 + 已上传的群文件（不可恢复） |

### 清单与信息图
| 你说的 | 会发生什么 |
|---|---|
| `今日JM` / `JM列表` | 发「本地书架」信息图：封面网格 + 编号徽章 + 标题 + 类型；已删除的本子自动消失 |
| `更新JM` / `今日更新` / `日更` | 发「站点当日更新」信息图（新上架/新章节，每 30 分钟自动采集） |
| `下好了吗` / `怎么没动静` | 查进度与最近记录（成功/失败原因） |
| `本地有哪几本` / `找找看` | 列本地收藏 |
| `支持 PDF 吗` / `群文件还有空间吗` | 报环境能力与群文件配额 |

### 按群开关（白名单）
| 你说的 | 谁能说 | 效果 |
|---|---|---|
| `开启JM` | 群主/管理员/白名单 QQ | 在**当前群**开启 JM；第一个群开启后进入白名单模式（只有名单里的群可用，私聊不受限） |
| `关闭JM` | 同上 | 关闭当前群；名单清空后自动恢复「所有群可用」 |
| `JM群列表` | 任何人 | 查看已开启的群（群号+群名） |
| `JM所有群开放` | 同开启权限 | 恢复默认：所有群都可用 |

未开启的群里：下载/清单/控制指令都会被婉拒，并提示管理员「开启JM」开通；消息里随手出现的数字也不会被当成下载请求。

## 4. 下载完成后发什么

1. **一张简介信息卡**（1344px 宽，和清单图同一套视觉）：
   - 左侧：大封面（圆角；本地图被清理时自动改用站点官方封面，再没有显示「无封面」占位）
   - 右侧：标题（简体/已翻译）、青色 `JM编号` 徽章、作者、标签、`N 话 · M 张 · PDF X 页`
   - 底部通栏：简介全文（简体，最多 8 行）
2. **一条文字**：交付状态——首次发车人（昵称+QQ 号）、上传结果（群文件/私聊文件）、失败说明。

「首次发车」只记第一个发 ID 的人，之后谁再发也不覆盖；认不出人时整行不显示，绝不写「群友」占位。

## 5. 设置项（QQ Agent 界面 → 技能 → 禁漫漫画下载 → 齿轮）

### 输出与还原
| 设置 | 默认 | 说明 |
|---|---|---|
| 输出格式 | `pdf` | `images` = 只存原图、零依赖、不上传 PDF |
| 还原竖切打乱 | 开 | 按站点返回的 `scramble_id` 还原；关掉最快但新本子是乱的 |
| 合成 PDF 后删除原图 | 关 | 开启省磁盘；**PDF 失败时自动保留原图** |
| PDF 画质 | 85 | 嵌入 JPEG 质量（30-95） |
| PDF 单页最长边 | 0 | 0=原尺寸；填 1600 可显著减小体积 |

### 上传与安全阀
| 设置 | 默认 | 说明 |
|---|---|---|
| 文件上传到哪 | `request` | 传回提出请求的会话；也可只传群/只传私聊/不上传 |
| 单文件上限 | 200 MB | 超限分卷（默认）或直接拒绝 |
| 上传前检查配额 | 开 | 群文件满员/满量时提前说明 |
| 允许触发的 QQ | 空 | 留空=所有人；填 QQ 号则只允许管理员/白名单触发下载 |
| 群文件保留天数 | 0 | 到期自动删机器人上传的群文件 |
| 本地保留天数 | 7 | 0=永不清理 |

### 网络与行为
| 设置 | 默认 | 说明 |
|---|---|---|
| 备用站点域名 | 空 | 域名失效时填可用的（一行一个，如 `18comic.vip`） |
| 下载走代理 | 空 | 服务器访问不了禁漫时填（如 `http://127.0.0.1:7890`） |
| 把日文标题翻译成中文 | 开 | 用对话模型翻译，结果按原文缓存；关掉只做繁→简 |
| 每话最多页数 | 500 | 防超长本子打爆磁盘 |
| 多章节全下 | 开 | 关掉只下第一话 |
| 同时下载几张 | 4 | 建议 ≤8，太大被站点限速 |
| 单次请求超时 | 30 秒 | 网络慢可调大 |
| 在群里报进度 | 开 | 关掉只报结果 |
| 启用下载功能 | 开 | 总开关 |

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 报「还原/PDF 不可用」 | 服务器没装 Python+Pillow：`apt install python3-pip && pip install Pillow`，或设置里填 Python 路径 |
| 信息图里数字/中文变「口口」 | 服务器缺字体：`apt install fonts-wqy-microhei` |
| 下载全部失败 | 域名被墙/失效：设置里换「备用站点域名」或填代理 |
| PDF 特别大 | 调低「PDF 画质」（如 70）或「单页最长边」（如 1600） |
| 上传报 20MB 超限 | 开自动分卷（默认）或调大「单文件上限」 |
| 「更新JM」是空的 | 没装 cron（见上文安装一节）；装好后等 30 分钟 |
| 群里发 ID 没反应 | ① 该群没开 JM（发「开启JM」）②「允许触发的 QQ」没加这个人 ③ 触发词不明确（试试 `jm` + 数字） |
| 翻译不工作 | 「把日文标题翻译成中文」被关了，或对话模型不可用（只影响标题，不影响下载） |

## 10. 加密压缩包（v2.4.0 新增）

PDF 合成完成后默认先打成一个 zip 再上传；不想打包就把第一个开关关掉。四个设置项在「技能 → jm下载 → 齿轮」里：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 0. 是否生成压缩包 | **开** | 关 = 回到原来的行为：直接把 PDF 传到会话，不打包、也没有密码 |
| 1. 是否给压缩包设置密码 | 关 | 关 = 照样打 zip，但不加密，消息里「解压密码」显示为「无」 |
| 2. 解压密码 | 空 | 开启上一项后才生效；建议字母数字（中文密码 Windows 自带解压可能报错） |
| 3. 是否把密码同步到压缩包文件名 | 开 | 开 = JM123456-密码：abc123.zip；关 = JM123456.zip（密码仍生效） |

- 文件名里的「Jm号」就是作品 id（JM<数字>）。**Windows 文件名不允许半角冒号**，所以写成全角「密码：」。
- 加密用 **ZipCrypto**（传统 ZIP 加密）：Windows 资源管理器双击就能输密码解压，7-Zip/WinRAR/Bandizip/手机解压 App 全兼容；强度一般，适合防随手转发，不适合存机密。
- 超长本子按页分成多卷时，**所有卷装进同一个 zip**；整包超过单文件上限（默认已调到 600 MB）时会整包试一次上传，**不再按字节切**（切开的 zip 解不开）。
- 实现在 `zip.js`：纯 Node、零依赖、1 MB 分块流式写入，几百 MB 的整本不会把内存吃爆；压缩方式为 STORE（PDF 本身已压缩）。

## 11. PDF 文件名（v2.5.1）

**压缩包里的 PDF 名字**：直接用 PDF 自己的文件名 `JM<作品号>-<作品名>.pdf`（分卷则是 `...part1of2.pdf`），
不再只写一个 `JM123456.pdf` —— 解压后一眼能看出是哪一本。

> v2.5.0 曾有过一个「在设置里改插件简介」的入口，v2.5.1 已移除（它要回写 `skill.json`，
> 手改清单时容易把 JSON 写坏）。简介直接改 `skill.json` 的 `description` 即可，
> 但**别在字符串里按真回车** —— 要换行就写 `\n` 两个字符。
