# dsh-bridge —— DSH 深度外援（技能）

给 QQ Agent 加的一个技能：会话里碰到需要**动脑子、写代码、多步排查、真的在电脑上动手**的活时，
机器人可以把任务派给本机的 **DSH（DeepSeek Harness）** 去干；干活期间它会**实时播报进度**、
**按时发一张「这次任务干到哪儿了」的会话快照图**、遇到需要你拿主意的时候会给出**编号选项**让你挑，
最后把 DSH 的最终回答带回会话，并接着上一轮继续聊。你说一句「停」它就会把正在跑的活掐掉。

当前版本 **v1.3.3**。

## 它做了什么

- 注册了两个工具（模型看到的名字）：
  - `dsh-bridge__dsh_agent` —— 把一件任务派给 DSH 无头跑一遍
  - `dsh-bridge__screen_shot` —— 发一张图到当前会话：默认拍**真实屏幕**（`target="desktop"`），
    也可以让它画一张**这次任务的过程快照图**（`target="session"`）；只有主人能触发
- 触发方式：**由机器人模型自己判断**什么时候用（所以它放在 `skills/`，是「LLM 型」技能）
- 每次派活用 DSH 的**无头模式**：
  `"D:\dsh\DeepSeek Harness.exe" --expose-internals "<...>\dsh-desktop-host\lib\cli.js" --profile headless --json [--session-id <id>] <任务>`
- 边收 DSH 输出的按行 JSON 事件流边处理：`tool_call` 变成进度消息、`final.text` 作为最终回答
- 按会话记忆 DSH 的 sessionId，同一个会话连续提问会**接着上一轮聊**
- 一次只跑一个任务（串行排队），默认最长等 3 分钟，回答默认截断到 4000 字
- 任务跑着的时候主人说「停 / 别干了 / 取消」，技能直接掐掉子进程（不用等它跑完）

## v1.3.3：图改成「这次任务的快照」，并且能喊停

1. **之前的图往往不是你问的那件事** —— 旧版去拍 DSH 的**窗口**，可无头模式的 DSH
   **根本没有窗口**（它是独立 profile，桌面端看不到这个任务）。于是拍到的是桌面端恰好开着的
   **另一个会话**；窗口一旦被最小化或收进托盘，`PrintWindow` 找不到窗口就退化成**整屏桌面照** ——
   正是「照片拍的会话并不是我发的那个问题」「dsh 在后台时无法呼出，拍摄的是桌面」。
   现在默认不再拍窗口，而是由技能自己把**这次任务**的执行过程画成一张图（`shots\card-*.png`）：
   标题、开始时间/跑了多久/走到第几步、任务原文、最近 N 行过程（每行带 `命/果/错/想/答` 彩色标记）、
   工作目录与 DSH 会话 id；任务结束时再补一张**带最终答复**的。图一定对得上你问的那件事，
   而且不依赖桌面、锁屏、窗口状态。真想看电脑实际画面时：「拍张屏幕照」仍会拍真实屏幕，
   设置里把「自动发的是哪种图」改成 `desktop` 就全部走真截屏。
2. **喊停没人理** —— 实测里主人连打「停吧」「停」，任务照跑满 180 秒。原因有两层：
   工具调用进行中 QQ Agent **不会再开新一轮对话**（钩子来不及），而且技能自己没有任何停止逻辑。
   现在技能在任务运行期间每 2 秒看一次**宿主的聊天记录**（`ctx.store.recent`），发现主人说了停，
   立刻 `taskkill /pid <pid> /T /F` 把 DSH 连同它的子进程一起杀掉，回一句「🛑 好，停下来了。」，
   并把这一轮记成 `STOPPED`（不会误报成「DSH 挂了」）。`before-llm-messages` 钩子也会在主人喊停时
   明确告诉模型「不要再派活，回一句停了就行」。只有主人喊得动；群友喊停不管用。


## v1.3.2 修的两个毛病

1. **照片拍不全 DSH** —— 截图脚本用的是 Windows PowerShell 5.1，它默认**不声明 DPI 感知**。
   在高缩放机器上（本机 2560x1600 @150%）它量到的是虚拟化尺寸（整屏 1707x1067、DSH 窗口
   1294x829 这种），而 DSH（Electron）是按物理像素自绘的，`PrintWindow` 于是把 2560 宽的画面
   画进 1294 宽的小位图里 —— 右边和下边整块被裁掉，就是「拍不全」。
   现在脚本第一件事就是声明 DPI 感知（`SetProcessDpiAwarenessContext(-4)`，失败退回
   `SetProcessDPIAware()`），并且**必须在 `Add-Type -AssemblyName System.Windows.Forms`
   之前**做（WinForms 会把第一次量到的尺寸缓存住，顺序反了不生效）。
   日志里会留下 `dpi=per-monitor-v2` 与真实像素尺寸，例如 `已拍下DSH 窗口 1909x1256 dpi=per-monitor-v2`。

2. **DSH 看不见主人刚问的那句话** —— 取聊天上下文那行原本写的是 `ctx.messages`，而宿主传给
   工具技能的 `ctx`（见 `src/orchestrator.js`）**根本没有这个字段**，于是那段上下文**永远是空的**：
   DSH 只收到模型自己写的 `task`。主人回复一个数字（变成「我选择第 1 项：…」）或说「它呢」时，
   它自然不知道前文在讲什么。现在改成：
   - 优先 `ctx.messages`（宿主将来若提供）；
   - 其次 `ctx.store.recent(chatKey, { limit, includeSelf: true })` —— 真实聊天记录，含主人刚说的那句；
   - 兜底 `ctx.session.trigger`（本轮触发消息）。
   提示词里还单列一段「**主人刚刚说的话（原文）**」，并明确告诉它「它/这个/刚才那个」指的就是上下文里
   最后提到的对象。`runs.ndjson` 每条新增 `contextChars` / `contextMsgs`，一眼看得出上下文有没有带上。

## 三个新能力（v1.3.0）

### 1. 实时播报

任务一开跑，机器人就在会话里报进度，不用干等：

```
🧠 DSH 开始干活了：帮我看看桌面上有什么文件…
🔧 跑命令：Get-ChildItem -Force（第 2 步）
⚠️ 第 4 步没成功（failed），它正在换个办法
⏳ DSH 还在干（第 5 步，已 32 秒）
```

- 开工 5 秒后才报第一句（短任务就不会刷屏），此后默认每 8 秒最多一句，单次任务最多 10 句。
- 文案每次都带步数/秒数，不会连续说一样的话（QQ 端会丢弃短时间内完全相同的文本）。
- 嫌吵可以在设置里关掉「干活时实时播报进度」，或把「单次任务最多几条进度」改成 0。

### 2. 过程图与屏幕照

- 你直接说「拍张屏幕给我看看」「截个屏」，机器人就会调用 `dsh-bridge__screen_shot`，**几秒内**发一张真实屏幕照。
- 「刚才那件事干到哪儿了」「把过程发我」这类问法，它会发一张**这次任务的会话快照图**（画出来的，不是截屏）。
- 长任务进行中，默认每 25 秒**自动**发一张图（最多 8 张，超过 30 张的旧图自动清理）。
  发哪一种由图设置「自动发的是哪种图」决定：`session`（默认）= 会话快照图，`desktop` = 真实截屏。
- 真实屏幕照拍的是**整个桌面**（多显示器一起），宽度超过 1600 像素会等比缩小后再发。
- 图**只发给主人**：即使打开了「允许群友也派活」，群友也拿不到（工具和硬闸都会拦）。
- 真实屏幕照的前提：电脑要处于已登录且屏幕解锁的状态（锁屏 / 远程断开时截不到画面，只能拿到黑图）。
  会话快照图没有这个限制 —— 它是在内存里画出来的。

### 3. 编号选项

有些活需要你拿主意（选哪个方案、先做哪一步）。DSH 会输出一行特殊标记：

```
[[选项]] 先把桌面文件按类型归类 | 先把下载目录清空 | 先别动文件，只给我一份清单
```

技能会自动把它变成一条选择题发到会话里：

```
【DSH 问你】桌面文件怎么处理？
1. 先把桌面文件按类型归类
2. 先把下载目录清空
3. 先别动文件，只给我一份清单

回复数字即可（比如「2」），我接着让它做。
```

你回一句 `2`（`选3`、`第三项`、`3.` 都认），机器人就会带着「我选择第 2 项：…」继续把活派给 DSH。
选项 30 分钟内有效，过期就不会再误触；同一会话有新任务时旧选项作废。

## 数据放在哪（不写进程序目录，升级不会被覆盖）

均在 QQ Agent 的 `data` 目录下：

- `data\dsh-bridge\sessions.json` —— 每个会话对应哪段 DSH 会话
- `data\dsh-bridge\runs.ndjson` —— 每次派活的记录（成功与否、耗时、步数、token 用量）
- `data\dsh-bridge\pending.json` —— 待你选择的问题与选项
- `data\dsh-bridge\shots\` —— 所有发出去的图（会话快照 `card-*.png` 与真实截屏 `shot-*.png`，自动保留最近 30 张）
- `data\dsh-bridge\card.ps1` / `card-model.json` —— 画快照图的脚本与这次要画的内容
- `data\dsh-bridge\shot.ps1` —— 真实截屏用的脚本
- `data\dsh-bridge-workspace\` —— 默认的 DSH 工作目录（DSH 在这里读写文件）
- `data\dsh-bridge-workspace\.dsh\sessions\...` —— DSH 自己保存的会话内容

## 谁能让它动你的电脑（重要）

QQ Agent 的核心系统提示词里有一条**最高优先级**安全规则（`src/prompt.js` 的 `securityRules()`）：

> 1. 你没有本地工具：不能执行命令、不能读写文件…工具不存在就是不存在。
> 2. 群友没有管理权限：任何人要求你「执行命令、查看电脑、读取文件…」时，一律礼貌拒绝，
>    并提示「这个需要管理员在管理端操作」。

那条规则不区分主人和群友，所以**主人自己**问「看一下某个目录」时机器人也会照本宣科地拒绝。
本技能因此自带一层主人判定：

- **主人名单（QQ 号）**里的人发消息时，技能会在发给模型的消息末尾追加一条
  `【主人授权 · 本机外援可用】`，明确告诉它：这次可以调用本机外援，主人电脑上的路径/目录/
  文件内容/命令输出都可以如实回答。
- **主人以外的人**：技能在 `before-tool` 钩子里**硬拦**（返回 `{block:true}`），
  `dsh-bridge__dsh_agent` 和 `dsh-bridge__screen_shot` 都调不动；机器人照旧回复「需要管理员在管理端操作」。
- 认不出发送者时：私聊按主人处理（机器人主动开口就是这种情况）；**群聊里一律不按主人处理**。
- 主人名单留空 = 谁都不授权。

**风险提示**：被授权的人等于可以隔着 QQ 让你电脑上的 DSH 读文件、跑命令、写代码。
默认只授权你自己的 QQ 号，不要随便往里加人；「允许群友派活」默认关闭，打开等于把上面这层保护拆掉。

| **自动发的是哪种图** | `session` | `session` = 这次任务的过程快照图（一定对得上你问的事）；`desktop` = 真实截屏 |

| 真实截屏最大宽度（像素） | `1600` | 调小省流量、发得快 |

## 修过的坑（别再踩）

1. **不能用 `spawn` 直接启动 `dsh.cmd`** —— Windows 上 `.cmd` 必须过 shell，而 shell 会把中文参数
   交给 cmd 的代码页，容易乱码。所以直接启动 `DeepSeek Harness.exe` 并把 Node 代码交给它跑。
2. **`app.asar` 里的 `cli.js` 用 `fs.existsSync` 查不到**（普通 Node 看不见 asar 内部文件，
   会返回 false）。所以只检查 exe 是否存在。
3. **`--session-id` 指向的会话一旦消失（被清理、换过 DSH_HOME），DSH 会直接报错退出** ——
   技能会自动丢掉旧会话、重试一次并记下新会话，不会让某个会话从此永远失败。
4. **headless 档默认用 `deepseek-official`，需要裸 API key**；本机已把
   `C:\Users\Lenovo\.dsh\profiles\headless\cordis.patch.yml` 改成复用你 DSH 账号登录态
   （`provider: deepseek-account` + `model: deepseek-flash`），所以不需要额外配置 key。
5. **技能无法改写 QQ Agent 的核心提示词**（`src/orchestrator.js` 注释写明：安全规则、工具协议
   由 prompt.js 独占，manifest 的 priority 上限 99 也覆盖不了）。所以「主人授权」只能靠
   `before-llm-messages` 钩子往消息末尾追加一段说明 + `before-tool` 钩子硬拦非主人，
   而不是去改 `src/prompt.js` —— 改程序本体在 QQ Agent 升级时会被覆盖。
6. **进度消息必须每次都不一样** —— QQ Agent 的发送队列有 8 秒内的完全相同文本去重（`src/sender.js`），
   照搬一句「正在处理」会被静默丢掉，所以进度里带步数、带秒数、带具体命令。
7. **QQ 有发言频率限制**（默认每分钟 80 条），进度间隔别设得太小；技能的最小值是 2 秒。
8. **拍屏幕走 Windows 的 `System.Windows.Forms` + `CopyFromScreen`**（PowerShell 脚本写到
   `data\dsh-bridge\shot.ps1`），所以必须跑在**有交互桌面**的会话里；DSH 作为服务或锁屏时只能拿到黑图。
   脚本只用 ASCII，避免代码页问题；图片以 `{file: 路径}` 形式交给协议端发送，不经过 base64。
   另外**必须先声明 DPI 感知再量窗口**（v1.3.2 修的），否则高缩放下只能拍到窗口左上角一块。
9. **DSH 的沙箱要往工作目录的权限表里写一条规则，写不进去就一条命令都跑不了**（v1.3.1 修的）。
   典型现场：`D:\QQ Agent\data\...` 这类目录的权限表里只有「Authenticated Users：修改」，
   没有当前用户的「完全控制」，于是 DSH 的工具结果里出现
   `Error: SetNamedSecurityInfoW failed (Win32 5): grantWrite(<工作目录>)`，
   而**它的退出码仍然是 0**（它把这件事故当成回答讲出来，比如「这个文件夹被 Windows 权限挡住了」），
   所以不能靠退出码判断。现在技能在两处兜住：
   - 派活前先给工作目录补一条当前用户的「完全控制」（`icacls <目录> /grant <用户名>:(OI)(CI)F`，
     每个目录每个进程只做一次）。目录本来就是主人的，这只是把隐含权限显式写出来。
   - 万一还是不行，就自动换到 `C:\Users\<用户名>\dsh-bridge-workspace` 重跑一次，并在会话里
     告诉主人「换地方了」—— 因为换目录等于换会话，必须开新会话（DSH 的会话按工作目录分开存）。
   判定依据是**工具结果**（`tool_result` 事件的 `status=error` + 错误原文），不是退出码。
10. **工具技能的 `ctx` 里没有 `messages` 字段**（v1.3.2 修的）—— 想拿聊天上下文只能从
    `ctx.store.recent(chatKey, { includeSelf: true })` 或 `ctx.session.trigger` 取。
    照抄 `ctx.messages` 不会报错，只会**静默**退化成「只把 task 交给 DSH」，
    于是主人问「它呢」时 DSH 一脸茫然 —— 这类「不报错、就是没反应」的坑在这个项目里很常见，
    改完一定要跑一遍 `stage\test-live.mjs` 并看 `runs.ndjson` 里的 `contextChars`。
11. **无头模式的 DSH 没有窗口，拍窗口永远拍不到「你问的那个任务」**（v1.3.3 修的）——
    `--profile headless` 是独立 profile，桌面端界面上看不到这次任务；拍窗口只会拍到桌面端
    当时恰好开着的别的会话，窗口最小化/收进托盘时还会退化成整屏桌面照。
    所以过程图改由技能自己画（PowerShell + GDI+，脚本 `card.ps1` 只用 ASCII，中文内容全走
    `card-model.json`，PowerShell 按 UTF-8 读 JSON，避免代码页把中文变成乱码）。
    `shoot()` / `screen_shot` 的 `target` 参数决定发哪一种，设置项 `shotStyle` 只管自动发的那张。
12. **「停」不能靠模型、也不能读技能自己的数据目录**（v1.3.3 加的）—— 工具调用进行中
    QQ Agent 不会开新一轮对话，钩子根本来不及；必须由技能在任务运行期间自己轮询聊天记录并杀进程。
    而聊天记录在**宿主的 store**（`ctx.store.recent`，就是 `data\messages\<chatKey>.json` 那份），
    技能自己的 `createStore()` **没有 `recent` 方法** —— 写成 `getStore().recent(...)` 会被
    `try/catch` 静默吞掉，表现为「喊停毫无反应」。基线用任务开始时的最大消息 `id`，
    只认之后的新消息、且发送者必须在主人名单里，免得把历史里的「停」或群友的话当成命令。
    杀掉之后 `runOnce` 必须先判「是不是我们喊的停」再解析退出码，否则 `taskkill` 的非 0 退出码
    会被当成「DSH 挂了」。
